## Product-fit adaptation of named skills

- `gpt-taste`: used its anti-slop, hierarchy, and contrast checks. AIDA, hero/footer, stock imagery, GSAP, and perpetual motion were rejected because they conflict with a high-stakes evidence workspace and the dependency-free prototype boundary.
- `design-taste-frontend`: applied a single accent, technical sans plus mono, rule-based grouping, focus-visible states, fail-closed states, responsive reflow, and reduced motion. Marketing density defaults were overridden by the owner's cockpit-density screenshot contract.
- `open-design-critique-theater`: critique is based on route-by-route screenshot deltas and task completion, not an acceptance score.
- `imagegen-frontend-web`: the existing four unified images remain the selected, coherent Scenario A system. No replacement generation was performed because the owner explicitly selected them as hard contracts.
- `image-to-code`: used copy-oriented reconstruction of geometry, density, typography rhythm, graph topology, and proof hierarchy; no aesthetic reinterpretation.
- `open-design-build-test`: verified the dependency-free bundle with syntax, browser, interaction, state, accessibility, overflow, asset, and repository checks. Project tests remain honestly skipped because no package manifest or test runner exists for this static prototype.
