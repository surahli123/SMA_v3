# Evidence Room Redesign Plan

## Replacement decision

Case Ledger is rejected evidence, not a visual base. Its editorial headline, repeated ruled regions, compressed metadata, and diagrammatic graph created a themed research dump rather than a fast review instrument.

Evidence Room rebuilds the DOM and information architecture around four reviewer jobs:

1. Understand the current conclusion, strongest support, strongest contradiction, and blocking gap.
2. Compare causal claims using a question-oriented Evidence Graph.
3. Reach exact deployed code/config authority and validator receipt within two interactions.
4. Replay execution without treating Trace as Evidence.

## System direction

- Persistent case rail and decision strip preserve orientation.
- Review uses an asymmetric conclusion/action composition and three evidence turns.
- Claims uses three semantic graph groups: Observation, Authority, Judgment.
- Verify uses deployed/candidate code and receipt projections.
- Trace uses a timeline and a separate tool-output inspector.
- Mobile uses a complete vertical typed path instead of squeezing a desktop graph.

## Skill applicability

- `gpt-taste`: anti-slop baseline, purposeful composition, and visible product states.
- `design-taste-frontend`: typography, spacing, asymmetric rhythm, accessibility, and reduced motion.
- `open-design-critique-theater`: honest visible baseline and iteration scoring.
- `imagegen-frontend-web`: four separate mode references used to select one consistent visual direction.
- `open-design-build-test`: structured evidence for syntax, links, browser behavior, responsiveness, and skipped test-runner status.

Marketing AIDA, hero/footer conventions, image-led storytelling, conversion CTAs, GSAP, scroll hijacking, and perpetual motion were excluded because they conflict with evidence authority, review speed, dependency-free scope, and accessibility.
