# DeepSeek Harness Practices for an Experiment Post Analysis Agent

**Status:** research/design only; no implementation or production authority
**Research snapshot:** 2026-08-14 (America/Los_Angeles)
**Decision:** adopt a small set of orchestration invariants, adapt read-only trace projection and lifecycle cleanup, and reject dynamic/model-authored execution plus every plugin that can write, restore, delete, install, or silently broaden access.

## 1. Executive recommendation

DeepSeek Harness is a useful reference for a replaceable execution harness, durable lifecycle events, effect-bound plugin cleanup, monotonic tool guards, fail-closed one-shot approval, explicit retry events, and crash-tail repair. It is not an enterprise evidence system. Its session log records execution facts, not experiment facts; its plugin system does not establish tenant authorization or source authority; its context summaries can shadow model-visible history; and its most dynamic extension path is explicitly equivalent to Bash access.

The smallest safe **spike/conformance profile** is below. It is not a selected Agent framework or target architecture; local authority leaves framework, vendor, and serialization choices unfrozen. Its exit criterion is conformance to the controls and tests in Sections 10 and 13; failure of a read-only, authority, determinism, or evidence-separation test rejects the candidate mechanism.

1. A fixed, reviewed, SHA-pinned bundle containing only allowlisted read-only adapters.
2. A bounded single-agent loop with durable turn/step/tool lifecycle events, explicit budgets, cancellation, and terminal failure propagation.
3. A non-replaceable enterprise policy/source broker, using Harness guards only as monotonic defense-in-depth inside one live `ToolRuntime`.
4. Deterministic crash-tail closure that records an interrupted tool as `unknown` and never blindly retries it.
5. A read-only trajectory projection for debugging and human navigation, outside the canonical Case Workspace.
6. An append-only typed Case Workspace, separate read-only Evidence Graph projection, deterministic validators/policy gates, and immutable human review packet.

For Codex, Claude Code, and Cursor portability, use host-native passive collectors behind replaceable adapters and an explicitly unfrozen Trace envelope. Do not turn three different transcript formats into a purported common protocol. Live lifecycle events are the preferred seam; version-pinned transcript parsing is optional backfill only.

Do **not** adopt dynamic Cordis packages, model-authored code, generic shell/Python, plugin marketplaces, automatic memory writeback, workspace rewind, plugin installation, provider fallback without a receipt, or any trace-to-evidence promotion. “Read-only Agent” means no production/source/external mutation and no generic write surface; it preserves only the canonical, schema-validated internal `Workspace.append` port.

## 4. Mechanism boundaries

These artifacts are intentionally different and must not be relabeled:

| Artifact | Canonical responsibility | Explicit non-responsibility |
|---|---|---|
| Execution harness | Run bounded read-only work; enforce tool lifecycle, cancellation, budgets, retries, and terminal outcomes | Does not decide source authority, causality, or production readiness |
| Plugin/capability system | Compose reviewed, fixed providers and intercept calls at declared seams | Is not a sandbox, package trust proof, ACL system, or evidence store |
| Trajectory/debug trace | Record calls, retries, errors, timing, and execution order for diagnosis | Is not Evidence, lineage, deployed-state proof, or a cause claim |
| Canonical Case Workspace / evidence ledger | Append typed source reads, observations, mappings, support, contradictions, claims, falsifiers, and receipts as the system of record | Does not execute tools, expose generic writes, or contain hidden reasoning |
| Evidence Graph | Project the canonical workspace into read-only typed relationships for navigation and review | Is not a truth store, mutation surface, or source of new Evidence |
| Deterministic validators/policy gates | Recompute numeric/schema/identity/coverage/policy checks and propagate ceilings | Do not make semantic causal judgments or grant action authority |
| Human review packet | Present immutable evidence, gaps, alternatives, gates, and exact query examples to named reviewers | Does not mutate/deploy and does not turn missing evidence into approval |

## 5. Official Harness findings

### 5.1 Architecture and lifecycle

The official architecture says every model adapter, tool registry, session log, and loop is a replaceable plugin, with no privileged core ([`docs/architecture.md:11-25`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/architecture.md#L11-L25)). Session events are durable; agent and capability events are live extension points ([`docs/architecture.md:45-59`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/architecture.md#L45-L59)). Turn, step, and tool events form an explicit lifecycle, and model-visible input must be reconstructable from the session log ([`docs/architecture.md:63-96`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/architecture.md#L63-L96)).

Useful adaptation: make execution transitions replayable and require every model-visible input to have a durable source. Required enterprise addition: bind each input to authorization, source snapshot, tenant, query/read receipt, redaction decision, and evidence-plane semantics. A logged model input is still not Evidence.

The project labels itself developer preview and warns of breaking changes ([`README.md:5-11`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/README.md#L5-L11)). Therefore, do not make its plugin API a stable enterprise contract without a compatibility adapter and pinned conformance suite.

### 5.2 Tool policy and failure propagation

The tool pipeline orders an extensible pre-execution waterfall, monotonic guards, one-shot approval, execution, post-processing, immutable final outcome, and one durable model-facing result ([`docs/tool-execution-pipeline.md:6-60`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/tool-execution-pipeline.md#L6-L60)). More precisely, the registry freezes the outcome and emits the live `tools/result` notification; the loop then appends one durable model-facing `tool/result` session event ([`packages/core/tools/src/index.ts:1656-1675`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/core/tools/src/index.ts#L1656-L1675), [`packages/core/session/src/types.ts:275-297`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/core/session/src/types.ts#L275-L297)). Registered guards are monotonic only within one live `ToolRuntime`, while the tool service and Harness composition remain replaceable plugins ([`packages/core/tools/src/index.ts:1453-1505`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/core/tools/src/index.ts#L1453-L1505), [`docs/architecture.md:11-35`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/architecture.md#L11-L35)); this is defense-in-depth, not a security boundary. Missing or unanswerable approval denies. Approval has a closed vocabulary; only `allowed-once` grants, while missing, throwing, or invalid answerers become unavailable and fail closed ([`docs/subsystems/approval.md:21-46`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/approval.md#L21-L46), [`84-88`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/approval.md#L84-L88)).

Adopt the monotonic-deny invariant but adapt its implementation into a non-replaceable enterprise boundary. Harness approval may authorize only a bounded read or disclosure. It cannot implement the canonical G7 Human Causal Ruling, packet acknowledgement, or Action Approval; those require separated roles, digest binding, expiry, supersession and re-acknowledgement, and still grant the Agent no external action authority.

The shipped preset table includes both `workspace-write + ask` and `danger-full-access + never` ([`docs/subsystems/permission-presets.md:11-48`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/permission-presets.md#L11-L48)). Neither is an acceptable production preset for this Agent. Use a distinct enterprise read-only capability profile with no shell, no generic filesystem writes, no deployment interfaces, and source-specific ACL enforcement.

### 5.3 Persistence, checkpoint/resume, context, retries, and budgets

The canonical session log is append-only, while derived model surfaces may use replacement events to shadow earlier content. Compaction preserves the raw log but changes the model-visible projection and retains failed attempts ([`docs/subsystems/session.md`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/session.md), [`docs/subsystems/compaction.md:9-21`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/compaction.md#L9-L21), [`69-117`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/compaction.md#L69-L117)). This is acceptable for context management only. Evidence, contradiction, authorization, and gate records must never be summarized away or shadowed in the canonical ledger.

Crash-tail repair deterministically closes incomplete lifecycle spans. A started tool with no durable outcome becomes `TOOL_OUTCOME_UNKNOWN`; the Harness does not automatically redispatch it, but its synthetic result asks the model to retry only when read-only or idempotent semantics establish safety ([`packages/core/session/src/repair.ts:89-131`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/core/session/src/repair.ts#L89-L131)). Persistence coordinates revision-bound prefixes, torn-tail repair, and contiguous durable batches ([`packages/session/session-persistence/src/coordinator.ts:91-193`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/session/session-persistence/src/coordinator.ts#L91-L193)). Adapt this as checkpoint/resume semantics with a deterministic policy gate—not model discretion—and verify evidence snapshot digests, authority expiry, policy version, adapter SHA, and idempotency class. A repaired Trace does not repair or prove external source state.

Model-request retry policy is provider-owned. `llm/retry` is appended before waiting and `llm/retry-started` before the next attempt. Normal mode is bounded by `maxRetries`; `always` mode has no attempt ceiling and retries every failure—including permanent authentication, quota, invalid-request, protocol, and unrecoverable-context errors—until success, cancellation, or disposal ([`packages/llm/llm-retry/src/index.ts:150-207`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/llm/llm-retry/src/index.ts#L150-L207)). Reject `always`. Adapt explicit retry receipts under enterprise ceilings: permanent authorization, ACL, invalid request, and unknown-side-effect outcomes never retry; every retry consumes a declared source/tool/cost/time budget.

The Harness has local limits for request output, cooperative tool deadlines, parallelism, compaction retry/tokens, output caps, and workflow items/children, but no unified per-case or per-tenant token, cost, wall-clock, source-read, page, or aggregate retry accounting; the default loop has no built-in turn ceiling, and `always` can issue unbounded requests. Fail-closed safety ceilings are mandatory now. Their numeric values, and ranking budgets, remain subject to sealed-pilot calibration under local authority.

### 5.4 Isolation, telemetry, and dynamic code

The Harness sandbox vocabulary governs filesystem effects, not network or process visibility. `danger-full-access` bypasses `ctx.sandbox`; enforcement can be `partial` (including older Landlock and Windows ACL cases), and only confined modes forbid silent unconfined fallback ([`docs/subsystems/sandbox.md:9-38`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/sandbox.md#L9-L38), [`152-170`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/sandbox.md#L152-L170)). Filesystem sandbox labels therefore cannot establish enterprise containment.

Session telemetry is best effort and may duplicate or drop records. Its redaction seam has no rules by default; without a listener, full payloads can be exported ([`docs/subsystems/session-telemetry.md:57-61`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/session-telemetry.md#L57-L61), [`124-126`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/session-telemetry.md#L124-L126)). Reject it for canonical evidence and disable export unless a deny-by-default field policy, destination policy, tenant isolation, retention, deletion proof, and secret scanner are in place.

Code Runtime executes model-written programs, and its worker/process/container `isolation` value is explicitly diagnostic rather than a security claim ([`docs/subsystems/code-runtime.md:132-175`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/subsystems/code-runtime.md#L132-L175)). Dynamic Cordis packages are stronger grounds for rejection: the official runner says `node:vm` is not a security boundary, live services remain reachable, and the feature should be treated like Bash access ([`packages/extensions/cordis-host-runner/README.md:28-38`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/extensions/cordis-host-runner/README.md#L28-L38)). Its timeout bounds only synchronous evaluation; async code escapes it ([`README.md:64-68`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/extensions/cordis-host-runner/README.md#L64-L68), [`sandbox.ts:217-233`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/packages/extensions/cordis-host-runner/src/sandbox.ts#L217-L233)). Reject Code Runtime and dynamic/model-authored plugins.

### 5.5 Plugin lifecycle

Cordis registrations are reversible effects that unload with their owning fiber. Async disposers are supported, but a component with missing services can remain pending, and a waterfall listener that omits `next()` can consume downstream behavior ([`docs/cordis-tutorial/02-lifecycle-and-effects.md:5-21`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/cordis-tutorial/02-lifecycle-and-effects.md#L5-L21), [`64-95`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/cordis-tutorial/02-lifecycle-and-effects.md#L64-L95), [`04-events.md:80-140`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/cordis-tutorial/04-events.md#L80-L140), [`06-composition-and-hmr.md:61-109`](https://github.com/deepseek-ai/deepseek-harness/blob/47f943859bef60e4160492346772ded9b24f765a/docs/cordis-tutorial/06-composition-and-hmr.md#L61-L109)).

Adapt lifecycle-bound cleanup, dependency health, and quiescent disposal. Add startup deadlines, mandatory dependency-failure outcomes, waterfall continuation tests, drain deadlines, and a process-level kill boundary. Lifecycle rollback is resource hygiene, not reversal of external emissions or evidence mutations.

## 6. Cordiverse paper: page-anchored claims and limits

The fixed PDF at `cordiverse/paper@948a07b369c62adb3b12e102458be5c18dfb69b9` contains 88 physical pages and was visually reviewed page by page. Coverage receipt: pp. 1–53 (front matter, motivation, calculus and design; reviewed, no additional material adoption claim), pp. 54–60 (runtime/effect findings below), pp. 61–65 (implementation exposition; reviewed, no additional material adoption claim), pp. 66–73 (case study, boundaries, capabilities and limitations below), pp. 74–75 (discussion; reviewed, no additional material adoption claim), pp. 76–79 (related-work/conclusion claims below), and pp. 80–88 (references; reviewed, no material finding). The following are **paper-author claims**, not independently reproduced results:

- Physical pp. 54–60 map the calculus to Cordis: context mutations flow through `ctx.effect`, inverses compose in LIFO order, provider withdrawal is ordered before dependency teardown, and asynchronous unload is drained.
- Physical p. 56 explicitly says the runtime does **not** verify that an author-supplied inverse actually recovers its effect. This limits cleanup guarantees to context-mediated operations with correct inverses.
- Physical pp. 66–67 present Koishi as a case study and describe a plugin ecosystem with over 4,000 community plugins. Koishi currently uses Cordis v3, while the paper presents v4 and claims a shared core compositional model (physical p. 66); adoption of v3 is not direct validation of the exact v4 implementation. Physical p. 67 further limits the evidence to one TypeScript ecosystem, calls it observational rather than controlled, and says overhead/productivity measurement remains future work.
- Physical pp. 67–68 distinguish inside-boundary reversible state from outside-boundary emissions. When recovery from an external emission is required, the paper offers withholding until persistence or application-specific compensation; generic effect rollback cannot retract the emission.
- Physical pp. 69–70 discuss declared capabilities and interception. For **proxy-mediated properties**, declared injection and interception form a reviewable request/mediation seam; this is not a universal ACL. For untrusted code that can reach host-runtime objects, language-level controls are insufficient, and the paper proposes software fault isolation, a separate runtime, sandboxed process, or virtualized container (physical p. 70).
- Physical pp. 70–71 make the language-agnostic claim conditional on closures, runtime introduction/retraction, declared dependency typing, and mediated dynamic access; reflection without direct mediation trades away type safety and developer experience. Physical pp. 71–73 identify further unresolved issues: dependency cycles leave components permanently inactive, decomposition can require quadratic integration-component growth, interfaces drift, keys collide, and peer-dependency compatibility relies on faithful semantic versioning and typically cannot host multiple versions of one package.
- Physical pp. 76–79 position Cordis against related work and conclude with a production-adoption claim, while explicitly presenting self-evolving agent harness validation as future work (physical p. 79).

Reviewer inference: use Cordis-style cleanup to make reviewed plugins unload predictably; do not infer malicious-plugin containment, evidence authenticity, ACL correctness, deterministic model output, or enterprise reliability from the paper.

## 11. M0, M1, and M2 application

M0/M1/M2 are a **noncanonical research crosswalk** for this review, not replacements for Scenario A's canonical eight stages. M0 maps primarily to intake, validity, and G1; M1 to identity, candidates, claims, independent challenge, and G2–G7; M2 to authoritative query/result evidence and the human packet.

### M0 — Flight Readiness

Use the harness only to schedule allowlisted reads and preserve lifecycle receipts. Deterministic validators, not plugins or model narration, recompute assignment, SRM, exposure, trigger/ramp, power, joins, interference, metric version, freshness, completeness, and guardrails. A failed critical check invalidates the affected interpretation and permits only validity, instrumentation, or data-quality recommendations. Missing reads or authority become Coverage Gaps.

### M1 — Metric Movement

Use bounded source adapters to collect candidate observations. Store raw authoritative reads separately from model-derived summaries. Require every ranked explanation to link supporting and contradicting evidence, scope/interval/rollout, alternatives, predictions, falsifiers, and a ranking receipt. Any ranking-bearing blind or pilot run requires a sealed non-production `pilot_ranking_policy`; no production ranking or GO is available before pilot calibration. Provider fallback, retries, and context compaction remain visible in Trace and cannot improve evidence strength. Neutral/mixed outcomes are valid endpoints; the system must not manufacture a code candidate.

### M2 — Win/Loss Evidence

Currently use only sealed, de-identified fixtures. Future read-only query/result retrieval requires P2 closure or an exact case-specific archival-snapshot authority receipt plus explicit field/path policy. It may then create ACL-safe examples tied to experiment arm, metric slice, surface, query, result, corpus/index/runtime identity, and source snapshot. A human packet shows exact examples, selection method, omissions, contradictions, and Coverage Gaps. Search summaries, screenshots, model reasoning, and trajectory records can guide navigation but do not substitute for the authoritative query/result read.

### Later production grounding

The requested production-grounding **subchain** is:

`metric -> surface -> query/result -> ACL/corpus -> pipeline/runtime -> exact deployed code/config/flag/model/data -> claim -> falsifier -> recommendation`

Each edge needs a typed source read or deterministic mapping receipt. It nests inside the canonical flow, which also includes observed/derived facts, typed change, alternatives, independent challenge and GateReceipts, orthogonal verdict/readiness axes, verification, and the immutable packet. Harness composition supplies none of these edges. The normal authority sequence is sealed authorization -> evidence collection -> Wayfinder ticket closure -> production GO. Before P2 closes, one blind historical case may be narrowly production-grounded only under a case-specific archival-snapshot authority receipt; that exception grants no live or broader access and cannot count as exact-target without exact deployed identity.

## 13. Required tests before any implementation adoption

1. **Bundle lock:** only reviewed SHA/digest-pinned plugins load; unknown transitive artifact, unsigned bundle, topic URL, or mutable tag fails startup.
2. **Read-only capability:** attempts to write filesystem, production database, index, flag, deployment, memory, message, or external system are denied before dispatch and produce a policy receipt. The sole write exception is schema-validated canonical records through `Workspace.append`; no plugin or generic filesystem API receives that authority.
3. **ACL/tenant:** cross-tenant IDs, unauthorized fields, pagination expansion, redirect, and inferred identifiers fail closed without revealing existence.
4. **Trace separation:** a Trace event without an Evidence receipt cannot satisfy any gate or support edge.
5. **Retry/fallback:** authorization and invalid-request errors never retry; transient retries are bounded and logged; fallback cannot masquerade as the requested source.
6. **Crash/resume:** interrupt before call, after dispatch, during read, before durable result, during compaction, and during packet render. Unknown calls are not replayed; invalidation begins at the earliest affected stage.
7. **Determinism:** fixed ledger plus validator/policy versions produces byte-identical receipts; model variation may change drafts but not hard gates.
8. **Compaction:** support, contradiction, source authority, ACL, and gate records remain unchanged and re-addressable after repeated context compaction.
9. **Plugin lifecycle:** missing dependency, thrown apply, omitted waterfall continuation, hanging disposer, async escape, and partial unload all yield terminal failures and no residual capability.
10. **M0/M1/M2 fixtures:** invalid experiment, mixed/neutral movement, material contradiction, missing authority, exact win/loss examples, wrong deployed SHA, ACL/index/pipeline failure, and correct abstention all reach the required ceilings.
11. **Host adapter conformance:** fixed fixtures for each supported host/version cover every documented event and ID, preserve unknown events as warnings, and never infer a terminal outcome from a start event or missing failure event.
12. **Observational no-op:** collector stdout and exit behavior cannot approve, deny, rewrite input, inject context, auto-submit a follow-up, or otherwise steer Codex, Claude Code, or Cursor. A missing required capture receipt blocks only the predeclared operational assertion or diagnostic view that depends on it.
13. **Capture coverage:** local/remote, main/subagent, disabled transcript, compaction, early validation failure, hosted-tool, and Cursor cloud cases produce an explicit capability manifest and Coverage Gaps rather than false absence.
14. **Resume/deduplication/order:** rotation, truncation, duplicate hook/backfill records, concurrent hooks, clock skew, interleaved resume, malformed complete records, and incomplete tails preserve deterministic source cursors and ordering confidence.
15. **Cross-host privacy:** canary prompts, paths, emails, commands, tool bodies, MCP results, credentials, and reasoning never enter the default Trace envelope, warning, log, error, or UI projection.

## 16. Agent-agnostic Trace across Codex, Claude Code, and Cursor

### 16.1 Decision and host boundary

Direct source reuse from Codex Trajectory is appropriate, but its Codex-only parser must not become the cross-host ingestion contract. The proposed seam is:

```text
host-native lifecycle seam
  -> host-specific passive collector + versioned adapter (ephemeral decode only)
  -> deny-by-default native field allowlist / redaction / secret scan
  -> strict, metadata-first TraceEnvelope
  -> append-only diagnostic Trace store
  -> per-render ACL / disclosure gate
  -> existing review projection
```

This is an **unfrozen engineering proposal**, not a selected framework, protocol, serialization, or change to canonical architecture. The collector/adapter may decode a native event only ephemerally; it must not log or persist the raw object, and prompt/tool/result/path/reasoning bodies are dropped before `TraceEnvelope` construction. Hooks are the preferred live feed because they expose lifecycle identifiers without requiring transcript interpretation. A transcript, command stream, or app-server adapter may provide version-pinned backfill where the host actually documents that surface. Reconciliation uses native IDs and source cursors, never timestamps alone.

Every collector is observational and returns the host's neutral no-op response. It cannot approve, deny, rewrite a tool call, add model context, stop a turn, or auto-submit another prompt. Collection failure is not allowed to steer the host. Every RunAttempt still emits a minimal Data Agent-owned lifecycle and resource receipt; that receipt is not cross-host Trace. Optional diagnostic Trace absence is a visible Coverage Gap, never negative Evidence or a global packet block. When a predeclared operational assertion or required diagnostic view depends on Trace, a missing capture receipt blocks only that assertion or view. Hooks therefore do not become the enterprise policy boundary.

### 16.2 Proposed `TraceEnvelope` and field provenance

All placement and naming in this envelope remain **unfrozen**. The table classifies how a value may be populated; it does not promote any field into canonical architecture. “Observed” means directly supplied by a trusted run/adapter manifest or native host event. “Inferred” means a deterministic adapter mapping. “Heuristic” means best effort and barred from gates. Missing native values remain null; they are never guessed.

| Proposed field(s) | Value provenance | Required rule |
|---|---|---|
| `trace_schema_version`, `event_id` | **Inferred**, deterministic from the approved schema plus pseudonymous source identity, epoch, sequence/offset, and native event identity | Version explicitly; collision test across hosts, rotations, forks, retries, and replay; never hash a raw body into the public ID |
| `observed_at`, `arrival_sequence` | **Observed** at the collector boundary | Collector clock and monotonic arrival order; never substitute for host occurrence order |
| `occurred_at` | **Observed** only when emitted; otherwise null | Preserve provider timestamp and basis; do not manufacture time from arrival order |
| `source_identity`, `source_epoch`, `source_sequence`, `source_offset`, `source_record_receipt_id` | Native stream/file identity and sequence are **observed** when supplied; stored identity/epoch/offset are **inferred**; the opaque receipt ID is **observed** from the secured pre-envelope intake | Use a tenant-scoped pseudonymous identity; do not use `mtime` as a cursor; defer incomplete tails. Any raw-record digest stays behind the secured receipt and outside Trace |
| `host_kind`, `host_version`, `host_event_name`, `host_artifact_digest` | Kind/version/event are **observed** from approved configuration/runtime; artifact digest is **observed** only from a trusted install manifest, otherwise null | Preserve the original event name even when normalized kind is `unknown`; version text is not an artifact digest |
| `native_session_id`, `native_turn_id`, `native_generation_id`, `native_prompt_id`, `native_tool_call_id`, `native_agent_id`, `native_parent_agent_id`, `pseudonymization_policy_version`, `pseudonymization_key_version` | Native values are **observed** only when supplied; stored pseudonyms are **inferred** through a tenant-scoped keyed transform; policy/key versions are **observed** from approved collector policy | Do not retain raw IDs or collapse different host identity hierarchies; versions identify the transform without exposing key material |
| `capture_mode`, `collector_id`, `collector_version`, `collector_digest`, `adapter_id`, `adapter_version`, `adapter_digest` | **Observed** from the approved collector/adapter bundle and configured seam | Allowed modes are host-specific; exact artifact digests and conformance receipt accompany every run |
| `kind`, `phase`, `status` | **Inferred** by a versioned deterministic mapping | Keep `host_event_name`; unknown stays `unknown`; start or missing failure never implies success |
| `operation_attempt_id`, `attempt_ordinal`, `retry_of_event_id` | Native attempt identity is **observed** when available; otherwise the normalized attempt ID/ordinal are **inferred** deterministically from the operation and source order | Never merge provider fallback, retry, or resumed attempts; unknown predecessor remains explicit |
| `duration_ms`, `usage_tokens`, `cost`, `load` and `measurement_basis` | Measurements are **observed** when emitted; paired-timestamp duration or price-table cost is **heuristic/derived**, and `measurement_basis` is an **inferred** label | Heuristic values are diagnostic only and cannot satisfy budgets or evidence gates without a deterministic receipt |
| `case_id`, `case_generation_id`, `run_attempt_id`, `stage_id`, `gate_id` | **Observed** from the Data Agent run context or validated Case Workspace link, not from the host | These local IDs are canonical elsewhere; their placement in Trace remains unfrozen and cross-links only |
| `redaction_policy_version`, `disclosure_level`, `safe_summary`, `projection_digest` | Policy/version are **observed**; digest of the already-redacted projection and metadata-only summary are **inferred** deterministically | Default envelope excludes raw prompt, query/result, command, output, path, email, MCP body, transcript body, reasoning content, and raw-content digest |
| `coverage_status`, `missing_event_classes`, `ordering_confidence` | **Inferred** from a session capability manifest; ordering confidence may be **heuristic** under concurrency/clock skew | Distinguish unsupported, disabled, expected-but-unobserved, delayed, malformed, and complete; absence is never negative Evidence |
| `cross_links` to `SourceRead`, stage, failure, or GateReceipt IDs | **Observed** only after validating existing canonical IDs | Trace may navigate to canonical objects but cannot create, mutate, or upgrade them |

No raw `payload` or `reasoning` field belongs in the default envelope. A secured pre-envelope intake receipt may retain an authorized integrity digest outside Trace; the envelope carries only its opaque receipt ID and a digest of the redacted projection. Separately authorized troubleshooting may re-open the original host source under its own ACL and retention policy; it does not copy that content into Trace or the human packet.

Each session also needs a capture-capability manifest: host/version, adapter digest, capture mode, configured event classes, known unsupported classes, transcript state, collection start/end, heartbeat gaps, and ordering basis. This turns Cursor cloud omissions, Codex hosted-tool gaps, Claude transcript lag, disabled persistence, and version drift into explicit Coverage Gaps rather than false claims that an event did not happen.

### 16.5 Threat controls and remaining unknowns

- **Hook command and ambient-secret risk:** all three host mechanisms can launch local commands. Ship only reviewed managed collectors by exact digest, with a minimal environment, no generic shell fallback, bounded local output, process isolation, and a one-way diagnostic append capability.
- **Hook privilege escalation:** host response schemas can block, rewrite, inject context, or trigger follow-ups. A conformance test must prove the collector always emits neutral output and has no permission/prompt/input mutation path.
- **Poisoned Trace:** host events, transcript files, and plugin output are untrusted diagnostic inputs. Preserve native source/digest and parse warnings; integrity does not make the contents Evidence.
- **Silent failure/retry/order:** concurrent hooks, lagging transcripts, fire-and-forget events, resume interleaving, and missing failure hooks require source cursor, gap intervals, attempt identity, and ordering confidence. Never infer completion from absence.
- **Correlated agent failure:** host subagent events can explain execution topology, but same-model or shared-context agents are not independent support. Independence comes from source reads, deterministic checks, frozen gold, and named reviewers.
- **Retention and deletion:** Trace retention may be shorter than Evidence retention. Deleting or rebuilding a Trace projection cannot delete, change, or invalidate canonical Evidence; it can only remove a navigation/debug surface and create a visible Trace Coverage Gap.
- **Digest boundary:** public software and approved releasable artifacts may use ordinary collision-resistant byte-identity hashes. Bare hashes of confidential content, secrets, or low-entropy values must not enter Trace, packets, cross-case indexes, or denial responses. Confidential content stays behind an ACL-scoped opaque receipt; an explicitly required equality check uses a versioned tenant-, case-, and field-scoped keyed commitment or non-reversible change indicator. A digest proves byte identity only. Credentials ordinarily retain no value-derived identifier.
- **Collector deployment boundary:** collectors may run only in Data Agent-owned, enterprise-managed runtimes for explicitly authorized Case Generations. Personal IDE/endpoint installation, unrelated-session collection, and employee performance or behavior monitoring are prohibited. Any future employee-endpoint collection requires a new authority receipt and any jurisdiction- and processing-dependent privacy or labor review.
- **Malformed required records:** a pin mismatch or malformed required record emits no normalized event for that source, records `unsupported | malformed` coverage, and blocks only the dependent operational assertion or diagnostic view. Canonical publication remains governed by Evidence Admission, GateReceipts, policy, and independent G7 review.
- **Redaction failure:** a collector emits a typed no-body `redaction_failure`, records blocked coverage for the dependent view, and never persists the raw pre-redaction object.

Explicit unknowns after this review:

1. Claude Code's published repository does not fix the CLI runtime, hook implementation, or transcript record schema; exact emission, ordering, and release behavior remain unverified.
2. Cursor publishes no inspected transcript record schema, default transcript location, rotation/tailing contract, or pinned editor runtime. Cloud hook coverage can vary by mode and remains unverified.
3. Codex `main` may be ahead of an installed release; hosted/specialized tool coverage and delayed/main-thread-only terminal events prevent complete lifecycle inference without a runtime conformance receipt.
4. No real cross-host fixture has established deduplication between hooks and backfill, clock/ordering behavior, fork/resume identity, or byte-cursor semantics.
5. Enterprise owners have not yet selected allowed host versions, collector distribution, Trace retention/redaction, raw troubleshooting authority, or required capture classes.
6. `TraceEnvelope`, its serialization, adapter API, capability-manifest schema, and the observability UI acceptance gate remain unfrozen. The field table is a proposal and cannot be treated as a canonical contract.

## 17. Bottom line

Use DeepSeek Harness as a reference for **bounded orchestration mechanics**, Cordis as a reference for **lifecycle cleanup**, and directly reuse the safe, licensed parts of Codex Trajectory for a **separate read-only Trace UI and Codex backfill adapter**. Put Codex, Claude Code, and Cursor behind distinct passive collectors and replaceable adapters; do not claim a shared transcript protocol or selected framework. Keep the enterprise truth path independent: source-authorized reads enter the append-only Case Workspace through the narrow validated port, the Evidence Graph remains a read-only projection, deterministic validators and policy gates compute receipts, and named humans review an immutable packet. The Agent remains externally and production read-only. No plugin, trace, retry, summary, or model reasoning can create evidence, authority, causality, or deployment permission.
