# Independent Evaluation-Design and Reviewer-Workflow Review — P3 / P4

Read-only review; no repo file was created, modified, or deleted. Priority items 2, 3, 4, 8 map to B3, B1+B2, B4, and M4.

## BLOCKERS

**B1 — Item 3. No difficulty floor, no trivial-baseline control, no planted-positive proof for the method itself. The fixture suite does not exist on disk.**
Docs observed: fixtures require "planted truth" and "planted defects and controlled perturbations" (`eval-acceptance-plan.md:33`, `wayfinder/evaluation-gold-calibration-contract.md:98`). Reviewer verification: `find docs/research/kdd-data-agent-workshop -iname "*fixture*"` returns zero files. No case set, no planted case, no negative control exists as an artifact. Searched `eval-acceptance-plan.md`, `evaluation-gold-calibration-contract.md`, `experiment-analysis-agent-evaluation-practices.md`, `enterprise-experiment-post-analysis-profile.md`: **ABSENT** — no target difficulty, no expected baseline failure rate, no trivial-baseline control ("always name the most recent deploy"), no adversarial-distractor requirement, and no requirement that a *weak* agent fail the suite. `enterprise-experiment-post-analysis-profile.md:381-407` lists 25 required acceptance cases — real coverage design, but coverage is not difficulty: all 25 are classes, none is calibrated against a control.
Consequence: a suite whose only correctness pressure is class coverage can be passed by an agent that recites the fixture's own planted metadata. Under the calibration principle this suite has unknown power and could plausibly sit above 80% pass by construction.
Correction: add (a) a mandatory trivial-baseline arm (most-recent-deploy heuristic + an always-abstain arm) run on every rung, with the rule that the Agent must beat both on required-candidate coverage while not exceeding the abstain arm's false-`confirmed` rate; (b) at least two adversarial fixtures where the most recent deploy is a decoy and the true cause is a config/data change; (c) a pre-registered rule that a fixture suite the trivial baseline passes is rejected before the Agent is scored.

**B2 — Item 3. Fixture-author independence is unconstrained.**
Docs observed: "Fixture author supplies deterministic truth; eval owner seals packets" (`evaluation-gold-calibration-contract.md:141`); fixture properties record a "fixture author" (`eval-acceptance-plan.md:33`). **ABSENT**: any rule that the fixture author is not an architecture author, and any rule that the blind-case curator is a different person. The four named owner roles (`evaluation-gold-calibration-contract.md:150`) cover labeling, not authoring.
Consequence: if the authors of `final-architecture-spec.md` also plant the defects, the fixtures test whether the design does what its authors intended, not whether the Agent finds causes. Highest-leverage power loss in P4; costs one sentence to fix.
Correction: in "Required case set", require that fixture authors and the blind-case curator are not authors of the architecture, policy, or prompt bundle under test, recorded as a packet receipt.

**B3 — Item 2. Blinding has no defined leakage detector, and model-side contamination is unaddressed.**
Docs observed: the freeze/blind procedure is real and specific — remove old RCA, patch, PR title, later telemetry, owner conclusion; "Run leakage and near-duplicate checks across prompts, filenames, fixture metadata, retrieval indexes, caches, and prior traces" (`eval-acceptance-plan.md:49-51`; `evaluation-gold-calibration-contract.md:75`). The corpus-contamination path raised in the task is closed **by construction for the frozen snapshot**: the archival receipt binds source and snapshot digests and permitted fields (`eval-acceptance-plan.md:52`), so an investigation-time snapshot mechanically excludes the later post-mortem, provided the snapshot is genuinely time-bounded.
Not closed: (a) the near-duplicate method is explicitly undefined — "the project must define its own near-duplicate rules for code diffs, queries, metric signatures, and incident text" (`experiment-analysis-agent-evaluation-practices.md:112`); no such rules exist in any file read. (b) Holdout invalidation covers only project-controlled exposure — "Any case used for training/fine-tuning, prompt tuning, or a manual exception is no longer a clean holdout" (`:110`); **ABSENT**: any treatment of the vendor model having seen the incident in pretraining. (c) Pre-labelers are blind to Agent output (`evaluation-gold-calibration-contract.md:78`), but the case curator selects the case knowing its resolution, and case-selection bias has no control.
Consequence: "one real blind historical Scenario A" can be asserted behind a leakage check whose method is undefined and unfalsifiable — a green leakage receipt would prove nothing.
Correction: specify the detector concretely (exact-string + n-gram + symbol-name overlap against the snapshot, thresholds pre-registered); require a prompt-freeze receipt dated before case selection; state that vendor pretraining contamination is unmeasurable, so a publicly or widely internally published incident is ineligible as the MVP blind case.

**B4 — Item 4. Two of the three owner-confirmed hard vetoes have no mechanical detector on the one case that matters.**
Docs observed: hard NO-GO = false `confirmed`, wrong exact patch target, security/privacy/tenant/ACL/authorization violation (`eval-acceptance-plan.md:170-174`), plus nine additional stop conditions (`:176-186`).
- *False `confirmed`*: mechanical against planted fixture gold; on the blind case the gold is a human adjudication (`evaluation-gold-calibration-contract.md:81`), so the detector is "a human notices". Partial mechanical cover: `G0–G7` ceilings and the deterministic policy-matrix receipt (`eval-acceptance-plan.md:119-128`) catch *unearned* `confirmed` (missing receipts), not *wrong* `confirmed`.
- *Wrong exact patch target*: the plan itself concedes that without exact deployed identity "the case may score abstention, evidence handling, and workflow behavior, but it cannot satisfy exact-target or production-grounding acceptance" (`eval-acceptance-plan.md:63`). P2 is open (`enterprise-experiment-post-analysis-profile.md:490`). On the MVP case this veto is very likely inert.
- *Security/ACL violation*: mechanical only if an enforcing source/authorization broker logs denials; that broker is design-only and explicitly unfrozen (`enterprise-experiment-post-analysis-profile.md:304`).
Consequence: the veto set reads stronger than it is. A veto with no detector is not a veto.
Correction: annotate each veto in `eval-acceptance-plan.md:170-186` with `detector: deterministic | human | not-yet-implemented`, and state that exact-target acceptance is out of MVP scope until P2 or the case-specific archival receipt closes.

## MAJOR

**M1 — Item 1. Set-valued gold is scoreable in principle but has no scoring function yet; two adjudicators are not shown to reproduce a score.**
Docs observed: assertions are `required | acceptable | forbidden | unknown` with "semantic equivalence guidance rather than a single expected string" (`evaluation-gold-calibration-contract.md:36`); measures are named — "Required-candidate coverage, acceptable precision, forbidden-candidate incidence, causal-role correctness, rank and retrieval depth of required candidates… do not freeze `k`" (`:107`). **ABSENT**: any matching rule from Agent output text to an assertion, any credit rule (partial credit appears only as a cited OpenAI practice, `experiment-analysis-agent-evaluation-practices.md:32`), and any aggregation — aggregation is in fact forbidden (`:102`). Matching algorithm and agreement-statistic selection are demoted to "engineering proposal" (`:79`, `:26`). Cross-adjudicator reproducibility is unestablished: Krippendorff's alpha and MASI are recommended, but the research records "did not find a unified alpha/kappa cutoff applicable to this task" (`experiment-analysis-agent-evaluation-practices.md:88,99`).
Reviewer inference: two adjudicators can reproduce the *hard gates* — exact-match agreement is required for them (`:79`) — but not the semantic candidate score. That split is defensible; the docs should say it rather than leave the scoring function open.
Correction: state that pre-pilot, only hard gates are score-bearing, and semantic assertions yield a disagreement inventory rather than a number until the matching rule is pinned.

**M2 — Item 5. The deferral is honest in form but circular in one place.**
`case inventory and count` is deferred to the pilot (`eval-acceptance-plan.md:232`; `evaluation-gold-calibration-contract.md:202`), while the pilot is defined as "Run the owner-confirmed blind historical case and de-identified fixtures first" (`:152`) — N=1 real case plus an unspecified number of fixtures. A distribution derived from N=1 cannot calibrate risk weights, `k`, or stability limits. The remaining deferrals are properly named and non-circular. Full table below.

**M3 — Item 6. Abstention has measurement but no reward.**
Docs observed: "Correct abstention receives credit", with required evidence = answerability label, Coverage Gap, expected dual-axis ceiling, applicable GateReceipts, prohibited action, and useful next safe check (`evaluation-gold-calibration-contract.md:177`); measures include justified versus excessive abstention, false `confirmed`, false `action_ready`, selective risk, coverage-risk curve (`:110`; `eval-acceptance-plan.md:145-148`). **ABSENT**: any relative weight — risk weights are open (`eval-acceptance-plan.md:233`), and the research states "no industry consensus on the specific cost weights, which must be calibrated by the owner and Eng" (`experiment-analysis-agent-evaluation-practices.md:203`). The only operative incentive is ordinal: false `confirmed` is a hard veto, abstention is not, and permanent uninformative abstention is a forbidden behavior (`evaluation-gold-calibration-contract.md:96`). That ordering is enough to prevent guessing-dominance in the MVP; it is not enough to score a pilot.
Correction: state the ordinal rule explicitly as the pre-pilot scoring stance so it is not mistaken for an unset gap.

**M4 — Item 8. P3's exit criterion is subjective; the surrounding protocol is better than "owner confirms it feels better" but is not a measurement.**
Docs observed: three acceptance scenarios, two of them measurable — exact code-line/config proof and its validator receipt reachable "within two interactions", and "A reviewer can see two conflicting claims without the default local graph hiding one side" (`wayfinder/prototype-observability-first-review-surface.md:37-39`); a feedback form with interaction-count and time fields (`prototypes/observability-review-surface/README.md:90-99`). **ABSENT**: reviewer count, reviewer role mix, which cases (only one synthetic hard-coded case exists, `prototypes/observability-review-surface/app.js:3-11`), any target value, and any pass/fail rule. Stated exit: "owner/reviewer confirmation that the interaction improves observability and review efficiency" (`README.md:103`; ticket `:52`). Plainly: as written, P3 closes on an opinion.
Correction — what would actually close P3: at least 2 real reviewers (one experiment owner, one code/domain reviewer), at least 2 cases including one where the Agent's conclusion is wrong, and a pre-declared pass rule — both reviewers reach exact proof in ≤2 interactions; both name the strongest contradiction unprompted; both correctly identify the stale-evidence recompute impact.

**M5 — Item 10. The surface does expose contradiction, staleness, and competing claims — but the competing-claim affordance is broken and most controls are inert.**
Right posture, observed in code: contradiction is first-class and blocking — `EV-MET-19` carries `"invalidation: unresolved; blocks confirmation"` (`app.js:15`) and renders in a dedicated `.contradiction` card stating "The segment contrast blocks a confirmed causal reading" (`app.js:106`); staleness is explicit with a FAIL validator and a 14 d age against a 24 h freshness limit (`app.js:16,107`); competing claims C-17/C-09/C-22 appear as Suspected / Inconclusive / Ruled out (`app.js:44`, `:120`); the header shows `Suspected` / `Blocked`, never a tidy confirmation (`app.js:7-8,67`). This is not a UI that makes a weak verdict look complete.
Defects: (a) claim nodes fall back to a foreign evidence ID — `data-evidence="${node[1].startsWith("EV-")?node[1]:"EV-DEP-17"}"` (`app.js:124`) — so clicking competing claim C-09 or C-22 opens the Evidence Inspector for `EV-DEP-17` "Validated support", which belongs to C-17. A reviewer inspecting a competing claim is shown validated support for a different claim. (b) "Show answer path" / "Show evidence path" carry `data-action="path"` (`app.js:134`) but `bind()` binds only `risk`, `relayout`, and `collapse` (`app.js:207-209`) — both buttons are inert. (c) Verify tabs Config/Diff/Receipts (`app.js:166`) and all Trace filters (`app.js:192`) are inert.
Correction: fix (a) before any live review — it actively misinforms; mark (b) and (c) as non-functional in the README so a live reviewer does not score them.

**M6 — Item 9. What `build-test.json` proves, exactly.**
It proves: `node --check app.js` parses; four routes render at 1586×992 and 390×844; four specific real clicks/keypresses change `?view=`; Claims `scrollWidth == innerWidth == 390`; no console errors; loading/empty/error/permission routes render; no CJK and no machine-local paths in durable artifact text (`build-test.json:18-34`).

## Verdict

P4 is a real evidence gate in its **veto** and **stability** layers: hard NO-GO items cannot be offset by an aggregate (`eval-acceptance-plan.md:176`), any hard-gate flip under frozen inputs stops the rung (`evaluation-gold-calibration-contract.md:162`), and "gold is not the old RCA" is enforced procedurally rather than rhetorically (`:81`, `:174`). It is **paperwork in its power layer**: no difficulty target, no trivial baseline, no planted-positive proof that the method detects anything, no fixture-independence rule, and zero fixtures on disk. As written, a determined team can produce a sealed adjudication packet with a clean receipt and learn nothing about whether the Agent can find a cause it was not handed.

P3 is closer to paperwork than P4. Two of its three acceptance scenarios are measurable, but the exit criterion is a subjective confirmation, the case set is one synthetic hard-coded case, and competing-claim inspection is wired to the wrong evidence record. The docs are unusually disciplined about not letting the prototype read as acceptance — that discipline is why P3 is repairable with a reviewer-count-and-target sentence rather than a redesign.
