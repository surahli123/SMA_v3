# Scenario A Causal Capability Review — Full Findings

## BLOCKERS

**B1. The `deployed-artifact → repo/file/symbol/line` hop has no specified derivation mechanism.**
*Spec observed:* the chain is required end-to-end — "typed code/config/flag/model/data candidate -> exact deployed SHA or artifact version -> file/symbol/line or exact artifact locator" (`enterprise-experiment-post-analysis-profile.md:175-177`); `code` targets require "Deployed artifact/SHA binding plus owner/repo, commit/tree, file, symbol, and line" (`final-architecture-spec.md:438`); "Do not invent false file-line precision" (`final-architecture-spec.md:444`).
*ABSENT — searched* `final-architecture-spec.md` §6.2 ports (176-193), §7.2 entities (209-231), §10.4 (430-444), §13, §17; `freeze-canonical-domain-policy-contracts.md` G0–G7 (266-277). No port, entity, receipt, or validator produces symbol/line attribution from a deployed artifact. `ProductionChangeRevision` lists "runtime identity, exact locator" as *fields* (`final-architecture-spec.md:220`) with no rule for populating them. `MappingResolver.resolve` (`:185`) is defined only by its return type.
*Production consequence:* every code-type candidate either abstains permanently, or the field is filled by an unspecified step — in practice a model reading a diff and asserting a symbol. That is exactly the "keyword proximity" tie the docs forbid (`planning-decision-packet.md:35`), re-entering through an unguarded field. "Wrong exact target" is a named hard NO-GO (`final-architecture-spec.md:123`).
*Correction:* specify an attribution port — e.g. `SymbolAttribution.resolve(deployed_artifact, affected_component) -> AttributionRevision | CoverageGap` — admissible only from build provenance (source map / debug info / package manifest) or a runtime stack/profile observation, never from a model reading a diff; and make G2 return `inconclusive`, not `pass`, when only file-level identity exists.

**B2. Win/loss per-query evidence is absent from the canonical architecture; its inclusion is an open owner decision.**
*Spec observed:* the profile defines M2 with a full per-example field list — "stable query or trace identity … side-by-side artifact or explicit counterfactual gap … `win | loss | unclear | not_comparable` judgment" (`enterprise-experiment-post-analysis-profile.md:203-215`). But *ABSENT — searched* `final-architecture-spec.md` §3.1 in-scope (65-76), §7.2 entities, §10.1 stages (380-389), §16.2 packet (644-655): no `WinLossEvidencePacket`, no per-query treatment/control comparison artifact, no judgment enum. Scenario A is canonically "post-experiment metric miss … explain why the target metric missed expectations" (`:32-34`); the only query-level content is a projection edge, "query/result/session" (`:568`). The profile itself lists "whether M2 is included in the first MVP" as unresolved (`enterprise-experiment-post-analysis-profile.md:451`) and requires the "query/trace join agreed" as an M2 *entry gate* (`:71`) — the join is not specified.
*Production consequence:* the owner's stated deliverable ("concrete win/loss query evidence") is unmet by the canonical spec; the MVP as frozen ships aggregate explanation only.
*Correction:* either add `WinLossEvidenceRevision` plus a `query_evidence` stage to §10.1 with the profile's field list, or state in §2 that Scenario A MVP does not satisfy the win/loss requirement and name M2 as the follow-on.

**B3. NEUTRAL and MIXED are not first-class in the canonical spec; the miss path is privileged.**
*Spec observed:* the profile does treat all four outcomes (`enterprise-experiment-post-analysis-profile.md:54-59`) and names the neutral failure modes — "true null, low power, offsetting wins and losses, or a segment-specific effect" (`:58`) — plus acceptance cases 3–8 (`:385-390`). But it also states that expanding "from a metric miss to every experiment outcome requires an explicit owner decision" (`:63`, restated as open decision 3 at `:452`). *ABSENT — searched* `final-architecture-spec.md` for `neutral`, `mixed`, `offsetting`, `underpowered`, `dilut`: zero hits outside "technology-neutral" and "mixed rollout".
*Production consequence:* a neutral read has no hypothesis family and no gate. Power appears only as a G1 *validity* input token, "trigger/ramp/power" (`:364`), so an underpowered neutral is either pushed into the invalid branch (blocking all system hypotheses on a possibly-real effect) or falls through to a miss-shaped candidate hunt. Neither is correct.
*Correction:* add `outcome_class = positive | negative | neutral | mixed` to `MetricQuestion` (`:211`) with per-class required hypothesis families (neutral: true null / underpower / dilution / ceiling / counteracting segments; mixed: related-metric coherence + trade-off reality), and a G1 rule that an underpowered-but-valid read yields `directional_only`, not invalidity.

**B4. `not_applied` is a label, not a mechanism; nothing prevents machine consumption of the diff.**
*Spec observed:* the diff "MUST be marked `not_applied` in both metadata and rendering", "bind to owner/repo and deployed revision", "never be written into a source worktree by the Agent" (`final-architecture-spec.md:450-458`). Authority prohibitions are strong and repeated (`:59`, `:109`, `:325`, `:351`, `:661`, `:829`).
*Reviewer inference:* a unified diff bound to an exact deployed SHA is directly `git apply`-able. The packet is a digest-bound machine-readable artifact delivered to a named recipient (`:644-655`), and `action_ready` is a machine-readable state whose only stated guard is prose — "No legal pair is Action Approval" (`:314`). *ABSENT — searched* §15, §16: no machine-checkable non-executable assertion, no prohibition on a downstream system polling `action_ready`.
*Correction:* require the diff to be non-applicable by construction (context-annotated fragment, or a mandatory sentinel that breaks `git apply`), and add a §16.1 publish-barrier predicate that the recipient channel is a human review surface, not an automation endpoint.

## MAJOR

**M1. Ranking is asserted, not reproducible.** Features are enumerated (`final-architecture-spec.md:508-519`), determinism asserted — "MUST produce byte-stable ordering" (`:525`) — ties break on "stable candidate IDs" (`:526`), each candidate gets an explanation (`:533`). But "Feature weights, risk weights, candidate depth/top-k … remain unset" (`:528`), and the pre-calibration `uncalibrated_fixture` policy (`:529`) has no defined comparator anywhere. A reviewer holding the packet cannot recompute the order — only re-run the same engine and observe agreement. Byte-stability is a replay property, not reproducibility. *Correction:* define `uncalibrated_fixture` as an explicit lexicographic ordering over gate-derived booleans (exact-identity → G2 status → mechanism support → contradiction count → candidate ID), reviewer-recomputable before any weights exist.

**M2. G6 can be emptied for unapplied proposals when replay authority is missing.** "For an unapplied Scenario A proposal, recovery and post-action recurrence are `not_applicable`; targeted pre-action replay/regression and guardrail checks **may** satisfy G6" (`final-architecture-spec.md:369`); the freeze doc is stronger — "Gate 6 cannot be wholly N/A merely because a Scenario A proposal is unapplied" (`freeze-canonical-domain-policy-contracts.md:277`). *Gap:* `not_applicable` needs only "a deterministic applicability receipt" (`final-architecture-spec.md:357`), and replay is P2-blocked (`:669`). No rule states that *missing replay authority* must yield `inconclusive`. *Correction:* replay/regression unavailable for authority, coverage, or budget reasons → G6 `inconclusive`, never `not_applicable`; reserve `not_applicable` for provably unreplayable change classes with a named human rationale.

**M3. "Material" inconclusive is undecided, and it is the sole hinge of the invalid-experiment block.** The block is otherwise a real gate with a defined enum transition — G1 critical fail → "effect Cause≤`inconclusive`; production Recommendation=`not_applicable`; only validity/instrumentation/data-quality fixes" (`:364`), reinforced by invariant 2 (`:116`), the branch rules (`:420-428`), and the publish barrier (`:628-638`). UNKNOWN validity *does* fail closed: "materially unknown validity state prohibits production-change … outputs" (`:116`), and "Timeout, no authority, zero reads … create Coverage Gaps, not Evidence=`observed`" (`:347`). *Gap:* the branch triggers on "a critical `fail` or **material** `inconclusive` result" (`:421`); materiality is a field (`:218`) with no classifier and no named owner. *Correction:* define materiality deterministically (any G1 check on the decision metric's assignment, exposure, join, or definition is material by construction) and default unclassified → material.

**M4. Segment/heterogeneity analysis has no multiplicity discipline.** Plane "Population and mix … head/tail query mix … heterogeneous regressions" (`:398`); acceptance case "segment-specific effect hidden by aggregate movement" (`enterprise-experiment-post-analysis-profile.md:388`). *ABSENT — searched* §10.2, §13, §19.2: no multiple-comparison control, no segment preregistration, no minimum-slice rule. Segment mining is the cheapest path to a false `suspected` on a true-null neutral. *Correction:* preregister segment sets in `ExperimentReadContract`, or flag them `exploratory` with a stated multiplicity adjustment, and forbid an exploratory segment from satisfying G3 alone.

**M5. Nothing forbids reusing the G3 observation as the G4 challenge.** G3 passes on "at least one runtime observation matches a prediction" (`:366`); G4 needs "at least one challenge complete with `challenge_result=supports`" (`:367`); "Repeated workers reading the same source are not independent corroboration" (`:695`) covers workers, not evidence reuse. *Correction:* add a G4 predicate that the challenge's SourceRead set is disjoint from the G3 supporting set, or that the challenge is a predeclared counterfactual (control/holdout/negative control), not a re-read.

## MINOR

**m1.** The profile leaves open "whether an invalid experiment may include an exact unapplied code/config proposal" (`enterprise-experiment-post-analysis-profile.md:125`, `:457`) while the spec already forbids it (`:423`, `:832`). Close the conflict in the spec's favor.

**m2. Abstention is genuinely first-class.** `Abstain` is canonical output behavior (`freeze-canonical-domain-policy-contracts.md:62`), invariant 12 (`final-architecture-spec.md:126`), a required case class (`:721`), and gold is set-valued so abstention can be `required` (`:727`). Budget exhaustion → "Partial immutable packet … next safe check" (`:689`); forced terminal submit is Rejected (`:786`); human timeout never approves (`:691`). **I found no specified pressure that can force `confirmed`** — ranking always emits a full list but is explicitly not a verdict (`:504`), and top-k is unset (`:528`). Residual: "justified/excessive abstention" is a measured axis (`:738`) with no floor; once calibrated it becomes the one lever that could punish correct abstention. Bind excessive-abstention thresholds jointly to false-`confirmed` rate, never independently.

## Item 1 — exact-deployed-tie chain, hop by hop

The specified path is `enterprise-experiment-post-analysis-profile.md:168-180` (production-grounding lane) and `final-architecture-spec.md:46-57` (required result chain), with type-specific exact identity at `:434-442`.

**Verdict on item 1.** Yes — there is a real specified mechanism stronger than proximity: the `scope × interval × rollout` matcher, and the docs enforce the prohibition ("Repository proximity, keyword similarity, a commit timestamp, or a graph edge is not a production tie", `enterprise-experiment-post-analysis-profile.md:182`). But the matcher's inputs are all acquired through sources that P2 has not named, and symbol/line has no derivation rule even in principle. The chain **fails safe** — G2 unknown/conflict caps Cause≤`suspected` and readiness=`blocked` (`:365`) — so it is not unsafe, it is **uncompletable**. The acquisition gaps are MAJOR because they are deliberate and gated; the symbol/line gap is a BLOCKER because a code-type candidate diff (`:448`) requires an exact target the architecture never explains how to obtain.

**Ceiling verdict.** `confirmed` is **not** reachable without reachability proof — G2 unknown/conflict hard-caps at `suspected` (`:365`) — so the reachability-BLOCKER condition does not fire. The real ceiling failure is upstream: under B1, a code-type `confirmed` rests on an attribution step with no specified evidence type at all.

## Item 8 — authority leak

No leak in the state machine: no Cause Verdict or Readiness value authorizes mutation (`:120`, `:314`, `freeze:203`); Action Approval is a separate human record that still does not authorize the Agent (`:661`); handoff crosses to "external authority only" by design (`:150-151`); "No UI action creates a source fact" (`:539`); no component holds production write, SCM write, deploy, rollback, messaging, or publication authority (`:325`). The candidate diff **is** explicitly marked unapplied in metadata and rendering (`:452`) and may never be written to a worktree (`:458`). The leak is B4: `not_applied` is enforced as a label and a rendering rule, not as a property of the artifact, and no barrier predicate constrains who or what consumes the packet.
